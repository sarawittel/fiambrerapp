# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Unofficial *Graveyard Keeper* guide as a native SwiftUI app for iOS 17+ (iPhone only) with a pixel-art look. It covers the first game (GK1) and, separately, the start of GK2 (items, recipes, characters, quests, technologies, achievements and the beginner guide so far). UI text, code comments and test names are in Spanish. Item names are translated to Spanish (`scripts/wiki/es_items.json`; the wiki name is kept in `Item.wikiName` and is searchable). Station and technology names are translated too (`scripts/wiki/es_names.json`; `Station.wikiName` keeps the wiki name). Characters without a proper name (Beekeeper, Bishop…) are translated in `scripts/wiki/es_characters.json` (`NPC.wikiName` keeps the wiki name; `convert.py` also swaps them in the prose, adding the article: «a Bishop» → «al Obispo»). Proper names and place names stay in English, as on the wiki.

## Commands

```bash
xcodegen generate                 # regenerate GK2Guia.xcodeproj (not versioned) after editing project.yml or adding/removing files
open GK2Guia.xcodeproj            # build/run from Xcode (simulator or device)

./scripts/test.sh                 # GK2Core tests; also works with only the Command Line Tools (adds Testing.framework flags)
./scripts/test.sh --filter PlannerTests/deep   # single test (args are passed through to `swift test`)
./scripts/ipa.sh                  # unsigned Release build/Fiambrerapp.ipa, to sideload with iloader (it signs with the Apple ID)
swift test --package-path Packages/GK2Core     # what CI runs (.github/workflows/ci.yml, macos-15)
```

Tests use Swift Testing (`@Test`, `#expect`), not XCTest. Only `GK2Core` has tests. The app target has none.

Regenerate data from the wiki (requires network; the cache goes to `scripts/wiki/cache/`, which is gitignored):

```bash
python3 scripts/wiki/fetch.py && python3 scripts/wiki/convert.py && python3 scripts/wiki/images.py && ./scripts/test.sh
python3 scripts/wiki_gk2/fetch.py && python3 scripts/wiki_gk2/convert.py && ./scripts/test.sh   # GK2
```

## Architecture

Two layers:

- **`Packages/GK2Core`** (SwiftPM, no UI): models, bundled JSON data and the planner. Everything that can be tested lives here.
  - `GameData` loads `Data/*.json` via `Bundle.module` (`GameData.bundled`) and builds lookup indexes. `recipe(producing:)` returns the **first** recipe for an output item. Both the planner and the UI depend on this, so the order in `recipes.json` matters. `convert.py` controls that order (`recipe_rank`): the recipe listed first on the item's own wiki page wins.
  - `Planner.requirements(for:recipes:deep:)` is a pure function. With `deep`, it expands craftable ingredients down to raw materials, reuses batch surplus (`outputQty`), treats cycles as raw materials, and returns intermediate `steps` with dependencies first. The planned targets themselves are removed from `steps`. The plan is iterated in sorted key order so output is deterministic.
  - `isStation(_:)` flags stations and buildings (item named like a station, or produced by a `Construcción · …` recipe). They can't go in a chest, so the chest search uses `searchItems(_:storable: true)`.
  - `Sprites.swift` holds 8×8 sprites as strings (one char per pixel, `.` = transparent) plus a palette. Entities have a wiki `image` (in `Data/Images/<image>.png`) and fall back to the `icon` sprite when it is missing.
  - `DataIntegrityTests` check every cross-reference: item IDs in recipes/NPCs, day IDs, icons, image files, sprite dimensions, and that the planner terminates on all recipes. Run the tests after any JSON or converter change.
- **`GK2Guia/`** (app target, defined in `project.yml`, depends on GK2Core):
  - `State/AppState.swift`: `@Observable` player state (`game`, `plan` = recipeId → count, `owned` inventory, `chests` = named player chests (`Chest`, item → count), `deepBreakdown`…). Each property persists to `UserDefaults` in `didSet` (keys `gk2.*`). Progress is per game: GK1 keeps the original `gk2.<name>` keys, other games use `gk2.<game>.<name>` (`AppState.key(_:for:)`). Changing `game` swaps `data` (`GameData.bundled(for:)`; GK1 and GK2 share nothing, see the GK2 section below), reloads that game's progress, and the `GameSwitch` button calls `Router.reset()`. `requirements` is computed on the fly from `Planner`.
  - `State/Router.swift`: shared navigation so screens can jump across tabs (e.g. ingredient → its recipe, → character). Each tab has its own stack path (`recipePath`, `characterPath`…); `open…` switches tab and pushes the detail.
  - `Views/ContentView.swift`: the current tab plus the bottom tab bar (four tabs and «Más» for the rest). `Views/Layout.swift` has `MasterDetail` (list → detail in a `NavigationStack`) and `SingleScreen`.
  - `Theme/`: palette, bundled pixel fonts (`.pixelTitle` = Press Start 2P, `.pixelBody` = VT323), `PixelBox` borders and `PixelIcon` (wiki image or sprite).

## Data

JSON in `Packages/GK2Core/Sources/GK2Core/Data/` (not named `Resources`: codesign rejects an iOS bundle with that top-level folder) is **generated** by `scripts/wiki/convert.py`. Manual edits get overwritten on the next conversion, so persistent data fixes belong in the converter. Hand-editing is still supported (see the README table for fields). Notable conventions:
- `characters.json`: `days: []` means the character appears every day. `quests` come from the `Quests`/DLC sections of each NPC page and `friendship` from sentences like "At 20 {{Happiness}}…". Both are heuristic (`REWARD_RE`, `REQUIRES`, `GAINS` in `convert.py`); `rewards` vs `items` is a best guess. Completed quests persist in `AppState.doneQuests` as `"npcId/questId"`, so keep quest ids stable.
- `days.json` order is the in-game week order. `data.day(after:)` wraps around. Days never appear by name in the game, so the UI shows only their icon (names are kept for accessibility labels only). In the prose, `convert.py` (`day_icons`) turns the days that came from `{{Day|…}}` into `![Orgullo](gk2://day/orgullo)`, and `RichText` draws them as an inline icon. Only days already in the English source are swapped, because in Spanish «Ira» or «orgullo» can also be the sin.
- `Item.quality` comes from the «Quality Levels»/«Quality» table (energy, value) plus the «Trading» table (first price column = `buy`, second = `sell`, first NPC wins); `value` is dropped when it equals `buy`. `Item.study` comes from the «Study» table. Prices are in copper coins (100 = 1 silver). The star images are `star_<level>.png`.
- Build recipes found on location pages get the station `"Construcción · <lugar>"`.
- Wiki prose is translated to Spanish via `scripts/wiki/es.json` (converted English text → Spanish), applied by `convert.py` at write time. When `convert.py` reports untranslated texts, add them there (keep the same `gk2://` links in the same order; `convert.py` then replaces item link labels that match the wiki name with the Spanish name). Untranslated item names go in `scripts/wiki/es_items.json`, stations and technology names in `scripts/wiki/es_names.json` (`convert.py` also swaps leftover English station names in the prose). Quest titles go in `scripts/wiki/es_quests.json`. Titles that match an item's wiki name use the Spanish item name automatically, and the quest `id` is still derived from the English title. Achievement names go in `scripts/wiki/es_achievements.json` (the wiki name stays in `Achievement.wikiName`, the `id` comes from the English name, and achievements quoted in the prose, e.g. `"Night watch"`, are swapped to «Spanish name»). Link texts that aren't the exact name (plurals, possessives, roles) are translated in `scripts/wiki/es_labels.json`.
- To add a new icon, add an 8×8 sprite to `Sprites.all` using palette characters only.

## GK2 data

GK2 is rebuilt from scratch from the GK2 wiki (graveyardkeeper2.wiki.fextralife.com). It shares **no** data with GK1, and its values differ (e.g. Iron Ingot). `scripts/wiki_gk2/` is separate from `scripts/wiki/`:
- `fetch.py` downloads the HTML of the hub pages «Items_and_Materials» (one item per linked page) «Characters» (character pages), «Technology_Costs» (one page per technology tree), «Crafting_Recipes» (recipe pages per station family: Woodworking, Metalworking…, plus Jewelry Table), and every page they link to, plus `EXTRA` pages only linked under «What to do next» (`Cooking_Recipes`, `Alchemy_Recipes`, `Workshop_Construction`, `Where_to_Buy_Materials`; keep it in sync with `EXTRA_RECIPE_PAGES` in convert.py) (cache in `scripts/wiki_gk2/cache/`, gitignored). The wiki doesn't serve wikitext (`action=raw` is disabled).
- `convert.py` writes `Data/GK2/items.json`, `recipes.json`, `characters.json` and `technologies.json` and downloads the icons to `Data/GK2/Images/<id>.png`. `Item.image` is then `"GK2/<id>"`, and `GameData.imageURL` resolves the `GK2/` prefix. Recipe tables (Output / Ingredients / Station and unlock, or the «Output per batch / Inputs per batch / Workstation and unlock» variant) and the Jewelry Table collar table are parsed automatically. Recipes repeated across pages are merged (`merge`). The cooking tables split station and unlock into two columns and write fuel as «10 Fuel (5 with Heat Saver)»; the reduced fuel goes to `notes`. Quality grades («Wine (silver)») are separate items, named «Vino (plata)». Alchemy formulas (Product / Red / green / blue / Example ingredients) are regular recipes at Laboratory I/II with `outputQty` 1 (the wiki doesn't give it). Each ingredient in the example fills one slot («Leaf + Leaf» = 2 Hojas), and the rune total goes to `notes`. For each recipe, extra stations, technology, extension and perk bonus go in Spanish in `notes`. Pages that are prose guides get their recipes and `sources` from the hand-curated `guide.json`, which goes first so it wins in `recipe(producing:)`, and their first paragraph as the description. Ingredients without their own page are items too.
- Translations: `es_items.json`, `es_names.json` (stations, extensions, technologies, perks) and `es.json` (descriptions). `convert.py` lists anything untranslated.
- `GK2DataTests` checks GK2's references, images and a few wiki values.
- Constructions (`construction_recipes`, `merge_constructions`): recipes with station «Construcción · <zona>», as in GK1, whose outputs are items and stations (`isStation`). They come from the per-area tables of «Workshop_Construction», the Zombie Gardening table (`PAGE_AREA`), `guide.json` entries with `"construction": true` (station guides that name the area) and the area-less «Construction uses» tables on any cached page. Identical costs merge and add their areas together. If any source gives an area, the area-less costs for that item are dropped. What remains goes under «Zona sin indicar», and differing costs carry a warning in `notes`. Images for items no page shows next to their name: first a GK2 wiki icon from `GK2_ICON_FILES` (file list in `cache/allimages.json`, from `fetch.py`). Otherwise GK1's image of the same item or station, matched by wiki name or `GK1_IMAGE_ALIASES` («Furnace I» → «Furnace») and copied into `Data/GK2/Images`. Quality grades use their base item's image. The GK2 wiki has no station images at all. GK1 images are the only thing GK2 takes from GK1.
- Characters: the «Characters» pages plus the merchants of «Where_to_Buy_Materials» (Builder, Tailor…). Title and location are hand-written in `guide.json` → `characters` (Spanish; proper names and places in English). The page's first paragraph (via `es.json`) and its portrait (`GK2/npc_<id>`) are used when the character has a page. `sells`/`buys` come from the «Trade by tier» tables and the Where-to-Buy tables, and the first trade level for each item goes to `notes`. GK2 has no days, so `days` is `[]` and the app hides the day filter, the «Días de visita» section and the «(todos los días)» text when `data.days` is empty. `ITEM_ALIASES` joins names spelled differently across pages («Flax Seed» → «Flax Seeds»).
- Talents (`talent_tree`): «Talents_and_Inspirations» (in `EXTRA`) becomes one more tree at the end of `technologies.json` («Talentos e inspiraciones», GK1's `tech_spiritualism` icon). Each first-tier inspiration in its table is a technology without cost; objective, goal and technology lock go in Spanish in `condition`, plus the «What counts for X?» paragraph for that inspiration. The tree `text` is the intro and the «Choose a use for points», «Zombie progression» and «Claim completed inspirations with Faith» sections. Inspiration names are in `es_names.json`.
- Beginner guide (`walkthrough`): «Beginner_Walkthrough» (in `EXTRA` in fetch.py) → `Data/GK2/walkthrough.json` (`GameData.walkthrough`, nil for GK1). The intro, the «Early progression checklist» table as `milestones` and one step per h2 (done steps persist in `AppState.walkthroughDone`, keep their ids stable). Paragraphs and «Page — what for» bullets are translated whole through `es.json`. Bullets link to the item or character when the page is one. Items and characters named in the English paragraphs (plural -s allowed) go in `items`/`characters`. The Guía tab shows a single «Guía para principiantes» row (route id `Walkthrough.routeId`) above the achievements. Tapping it opens the steps as checkable cards.
- Achievements (`achievement_guide`): «Graveyard_Keeper_2_Achievements» (in `EXTRA`) → `Data/GK2/guide.json` (not to be confused with the hand-curated `scripts/wiki_gk2/guide.json`). One `GuideSection` per table, in page order; sections inside `kiln-spoiler` get `spoiler: true`. Section `name` is already Spanish (via `es.json`; `GuideSection.title` only translates GK1's). Achievement names go in `scripts/wiki_gk2/es_achievements.json` (`id` from the English name, which stays in `wikiName`) and descriptions in `es.json`. Characters named in the description go in `characters`. The GK2 wiki has no achievement images, so they show the crown sprite.
- Quests (`quests`): the guides linked from the «Quests» hub (in fetch.py's `HUBS`), one per page, go into `quests` of the character whose portrait caption the page shows («Herbert character portrait from the game.»). `text` is the intro plus one «**Etapa.** texto» paragraph per h2, all through `es.json`. The quest name is translated in `scripts/wiki_gk2/es_quests.json` (the English one stays in `wikiName`, and `id` is its slug). `swap_quests` also replaces English quest names in the text fields of every output file with «Spanish name» (in bold link labels, without the quotes), so add any quest the prose mentions to `es_quests.json`. Items and characters named in the English text go in `items`/`characters` (`mentions`, plural -s allowed). They show in the character's detail and in the Guía tab's «Misiones» panel, one row per character that opens their quests (route id `quests/<npcId>`, `QuestsGuideView.routeId(_:)`), and count as «Misiones» in «Juego completado».
- Technologies (`tech_trees`): one tree per «*_Technologies» page linked from «Technology_Costs», in its order, with a single unnamed branch. Cost is «Red / green / blue» (zeros dropped). Prerequisites become `requires`, and «<NPC> reputation N» and «Hidden at start» go in Spanish in `condition`. Cooking techs cost nothing, and their «How to unlock it» goes through `es.json` into `condition`. `unlocks` come from the recipes whose station column names the technology («Technology: X»): `blueprint` for constructions, `recipe` otherwise. A recipe technology missing from the tables stops the conversion. Names shared by two trees are resolved with `UNLOCK_TREE` («Fabric» → Building). Tree names are in `es_names.json` as «<Tree> Technologies». Tree icons are GK1's `tech_*` images copied to `GK2/tech_<id>`.
